## Devices 电脑详情与项目入口 — 2026-11-05

Devices 默认以电脑名称、系统、项目数量、最近设备回报和登记授权区分执行电脑；
Enter 打开电脑详情，不再直接进入内部编号组成的任务清单。详情展示授权到期时间、
Codex 的登记能力和历史版本回报、可选择的项目名称及完整登记路径。目录不是当前
终端的工作目录，也不证明此刻存在或可访问。云端尚无本机权限信息时明确显示未知。

↑/↓ 选择项目，N 打开现有 Work 新建流程并预选同一电脑/目录，仍需重新读取目标、
编写任务、完整审阅和显式确认。刷新按电脑/目录 ID 保留选择；原目标被移除或失效时
保留草稿，停止选择，不自动替换为其他电脑/目录。不确定提交仍优先恢复原请求。

C 仅检查云端连接并重新读取设备信息；最近读取时间与历史设备回报时间分开展示。
当前协议没有运行心跳，登记有效、历史版本或目录回报都不能显示为服务在线、Codex
登录正常或可写文件。I 展示在执行电脑上的启动/恢复说明，不执行安装或进程控制。
F7 展示编号、版本、回报序号等诊断（不展示凭据及指纹）；T 才打开该电脑任务清单，
明确它可能含其他聊天的任务。Esc 从清单返回详情、从详情返回电脑列表。

详情支持滚轮和 PgUp/PgDn，窄窗口使用精简键位提示。既有头像、侧栏、Chat/Work
阅读与复制保持原有边界。无需更改 Kernel、数据库或设备服务。

## 滚动与拖选坐标修复 — 2026-11-05

Chat 和 Work 的阅读器只在实际布局改变、且没有新滚动请求时恢复源位置锚点；普通重绘
保持用户指定的滚动行。空行保存真实正文位置，代码标题保存代码块索引，不再把空行或
任意代码标题当成整条消息开头。后台新增内容时，阅读中的位置仍按对应正文/标题恢复。

鼠标命中使用最后实际绘制的视口位置；开始拖选冻结当前显示页，不使用尚未绘制的滚动
目标。拖选方向比较正文锚点，不依赖换行前的屏幕行列。第一行和最后一行仍属于视口，
只有指针越过视口上下边缘才请求自动滚动。被选择正文版本改变或来源失效时清理选区；
正文复制仍经过现有受检来源、版本和剪贴板代际边界。

## 可辨认的 Work 列表与逐轮时间线 — 2026-11-05

Work 列表以原始任务摘要区分会话，显示最近设备回执时间、本地时区偏移、状态、轮数、
执行电脑和登记的工作目录。选中项下方显示创建时间、最近指令和目录；侧栏同步显示
登记路径。设备目录尚未读取时明确显示“目录待同步”，不以终端启动目录代替。缺少根
轮次时标记原始任务待载入；Kernel 本机 Worker 保持独立来源，不伪造设备时间或任务。

Enter 默认进入“你的原始指令 → 该轮 Codex 回传 → 追加指令 → 下一轮回传”的时间线。
每轮有创建/回执时间和独立的正文复制，追加不覆盖旧结果。读取最近快照之外的祖先时，
仅使用已有的 conversation-bound GET，并检查设备、会话族、父子关系和工作区范围。
每次最多载入 64 轮；历史缺失、范围不符或有界读取未完成时明确提示，不补造正文。
认证/协议失效仍交由原同步机制清除受检视图及复制能力。

每页至多 8 轮，同时按显示容量提前拆页，避免大量换行越过阅读器滚动上限。F5 查看更早
一页，Shift-F5 返回较新一页。翻页只改变阅读窗口；F4/F6/F8 仍操作所选任务，F7 保留
该轮完整诊断。时间来自真实创建时间/设备回执接收时间，不声称是精确执行时长。
每轮 output_tail 仍最多 2048 字节，原截断标记继续显示；逐轮历史不等于完整原生终端。

## 紧凑动态卡片与独立结果阅读 — 2026-11-05

Chat 中的设备任务更新现在使用稳定任务 ID 的紧凑卡片。同一任务在原位置更新，不再重复
追加 Device/Command/Kernel state 等整段诊断。正在执行的常规状态由侧栏和 Work 承担；
结果返回、权限待处理、取消和异常提供卡片入口。点击“查看结果”，或 F7 打开动态菜单后
Enter，进入同一任务的 Work 页面；这些操作只读取、导航，不派工、不确认权限。
菜单同时显示简短任务文字和短 ID，区分重复任务。

Work 默认使用共享 Markdown 阅读器展示设备实际回传正文，支持正文选区、F2 纯文本／
Markdown／代码复制、F3 阅读及滚动。Chat 和 Work 拥有独立正文、菜单、选择和剪贴板代际。
当前服务端仅回传有界 output_tail（最多 2048 字节）；回传不完整时明确标为“节选”，
不把它称为完整执行日志。F7 在结果和原诊断之间切换，完整 ID、执行证据、命令错误、
权限决定与截断标记均保留。F4 审阅、F6 追加、F8 取消仍使用原有精确范围与审批流程。

普通 Actor 工具回执默认收成一条短动态，点击“展开”或 F7 菜单查看原回执详情。待确认、
失败和未知结果有明确标题；没有自动确认或重试。Kernel Worker 通知按原 action ID 合并，
冷启动已知的完成／取消回执不补刷，异常仍可见；未显示的回执不加入 /seen 的确认集合。
Kernel Worker 旧通知的展开是有界原回执，既有 Work 控制入口保持原状。

冷启动和任务流重连的首个快照仅恢复历史工作列表，旧完成任务不会成为新聊天消息。
正常受检同步可临时保留卡片身份、已见版本、时间高水位、已知通知 ID 和稳定消息锚点，
不保留标签、任务文字、输出或原签名。失效时仍立即清正文、选择、菜单和复制代际；
取得新受检正文后才恢复卡片位置。身份/协议/传输错误清理这些临时元数据。
缺失历史锚点时回退到当前历史顶端，不把旧卡片移至最新对话下方。台账有界、不落盘。
折叠详情计入原正文缓存上限，详情本身最多 4000 字符并显式提示截断。

## Work 直接新建任务与多行粘贴 — 2026-11-05

Chat 用于与 Lain 对话，Work 用于直接创建和跟踪工作，Devices 用于电脑连接与诊断。
Work 按 N 选择已声明支持 Codex 的电脑和工作区，再输入任务；F5 选择只读／工作区写入，
F7 选择有限时限。Enter 预览精确原文和范围，完整阅读后 Ctrl-Y 才提交，不调用聊天模型。
权限仍受设备本地策略及 Worker 实际审批约束。任务详情保留进入时的 Work／Devices 标签来源。
返回 Chat 和退出界面不取消任务，聊天与任务草稿独立。

提交前核对设备快照和按原请求查询回执的接口；旧服务端缺少该接口时，在派工前停止。
发送结果不确定时保持原请求，Ctrl-R 只查回执，不能重新排队。断线关闭目标选择和审批，
保留本进程的草稿及未决请求；跨进程草稿恢复尚未实现。详见 [Work 交付范围](WORK_DESK.md)。

F9 为显式本机剪贴板文本粘贴入口，支持 Chat、任务和追加输入；不会自动发送。输入中途
切页或修改草稿后，迟到的剪贴板结果丢弃，超长文本整次拒绝。Windows 实测普通终端粘贴
可能在底层按键路径丢换行，因此多行任务使用 F9；收到真正的 bracketed Paste 事件时也
保留原文。原生 ConPTY 隔离测试已验证 F9 多行原文、只排队一次、返回 Chat 保留草稿和
退出后任务持久化，零真实模型／Worker 调用；不是云端或付费 Provider 验收。

## 滚轮历史与本机信息侧栏 — 2026-11-05

统一终端接收鼠标滚轮事件。仅鼠标位于 Chat 正文内时滚动已载入历史，每格移动三行；
输入框、头像侧栏和审批页不会把滚轮当作提交或审批。向上阅读时暂停自动跟随，新输出
不强制拉到底部；向下到达底部恢复跟随，Ctrl-End 直接回到最新。进入 Worker 子界面前
释放鼠标捕获，返回后恢复；退出／异常清理先恢复鼠标模式，再恢复普通终端输入模式。
PgUp/PgDn 仍可使用。当前启动快照仍最多二十轮，正文缓存仍最多 128 KiB，超过后保留
约 96 KiB；这是已载入历史的滚动，不是无限归档分页，不能宣称全部旧记录已加载。

宽屏头像下显示本机 OS／架构、可用逻辑核数、物理内存已用／总量、本机当前目录、
任务工作区和进行中／待处理任务。内存每五秒读取一次操作系统接口，不启动 fastfetch、
外部命令或模型；“已用”为物理总量减可用量。Windows 使用 GlobalMemoryStatusEx，
Linux 有界读取 meminfo；macOS 目前只提供物理总量，已用显示未知，原生 macOS 尚未验收。
接口依据见 [Microsoft 文档](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-globalmemorystatusex)
和 [Apple XNU 内存 sysctl](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_mib.c)。
读取失败不显示伪造的零值。本机信息只留在本进程呈现，不上传 Kernel、不进入提示词或记忆。

本机目录和 Kernel 工作区分别标明；纯聊天没有工作区时显示未选择。设备工作区保留真实
设备／workspace ID，不能将它解释为本机或云端路径。当前普通 Work 选中项可显示 Kernel
提供的真实 workspace；较长路径有界换行。普通窗口高度省略重复的会话 ID／分组空行，
给任务留出空间；窄窗口继续优先正文，头像原文不被裁成小脸。

任务区合并当前 Lain 回复／待审批状态、Kernel 受管 Worker 和当前对话关联设备任务。
Kernel 会话用明确的 Kernel 前缀区分来源，设备排队／接收／报告运行保持其真实状态，
不推断设备在线。复用已有 Worker 事件流和设备任务订阅，无额外后台模型调用或任务控制。
Worker 显示缓存最多 512 项，溢出／断线明确说明不完整；断线或来源代际失效后不再把
旧任务快照显示为当前运行。详细工作和控制仍在 Work／Devices 页。

原生 Windows 客户端测试 92 项通过（一项既有手动检查忽略），CLI 一项通过；原生 ConPTY
十三项检查覆盖真实滚轮、Ctrl-End、宽窄尺寸、侧栏、草稿、重连及审批。六次模拟模型请求，
零付费调用。测试解析器宽字符被 ASCII 覆盖后的空占位异常另有最小复现与测试；兼容处理
仅在测试字符流展示层，不修改生产绘制或安装的第三方库。图片是实际 ConPTY 字符流的
字体渲染，任务来自隔离模拟服务，不能标成真实 Windows Terminal 桌面窗口或真实 Worker 工作。

## W4 权限事实与任务取消 — 2026-11-03

任务详情分别展示云端已记录决定、设备报告已收到、Worker 报告已确认。只接受精确匹配的
决定和设备证据；轮次结束、提示消失或云端 HTTP 成功不替代应用确认。缺少确认保持未知。
权限增量已通过 368 项 Rust 检查、16 项原生设备服务、11 项工作链和 8 项终端回归。

统一任务取消入口已通过本地原生隔离验证：设备任务详情 F8 打开完整目标，逐页读完后 Ctrl-K 明确
请求取消；Esc 关闭无副作用，Tab 返回 Lain，草稿保留。发送前重新读取同一任务及版本；
任务变化须重新审阅。退出前端不是取消，取消不撤销既有操作。

不确定回执用 Ctrl-R 读取当前事实；同版本且未见取消不能证明原请求失败。
`/cancel-retry` 仅明确重试原始版本，不能自动采用新版本。当前任务已记录取消请求时，
只能证明存在该请求，不能归因于本客户端；原版本已变化且未记录取消时，旧版本失去
后续执行资格。设备报告 Cancelled、云端排队取消与原生终止未确认分别呈现。
同一任务的新终止／完成证据会更新底部取消提示；迟到的旧回执不能盖过已知的新事实。
这是前端临时提示状态，不新增请求、模型调用或执行权限。
完整阶段验收见 [W4 对照](W4_ACCEPTANCE.md)。

## 入口与归属

直接运行 `lain` 或 `lain desk` 进入统一终端。默认创建新的 Kernel 对话；
`lain desk --conversation <id>` 恢复指定对话，顶部显示完整 conversation ID。
不会自动连接 QQ 私聊对话，也不会在本机创建另一个人格或同步人格文件。
`lain chat` 保留原有逐行入口；`lain work dashboard` 保留独立 Worker TUI；
`lain work attach <id>` 继续观察指定受管 Worker。

界面只连接已有 Kernel。进入界面不启动设备服务、不安装系统服务、不调用模型。
在连接失败或不具备真实终端时应退出并给出错误；脚本继续使用明确的 JSON 命令。
无 npm、浏览器或 Web 依赖。

## 当前视觉与资源入口

2026-11-03，用户认可 A 头像及宽窗口侧栏/开场展示的效果预览。当前 Rust 实现保留所选
29 列 × 18 行字符原文，不再使用被否定的手绘脸，也不通过修改眼睛字符虚构表情。
真实连接、Actor 和待确认状态继续以文字表达；后续表情帧必须单独设计并验证。

```text
lain desk --portrait <absolute-local-utf8-text-file>
lain desk --conversation <id> --portrait <absolute-local-utf8-text-file>
```

也可显式设置 `LAIN_PORTRAIT_FILE`，供 `lain` 或 `lain desk` 读取；命令参数优先。
启动时最多读取 8 KiB，只接受恰好 18 行、每行 29 个单列可打印字符的 UTF-8 文件；
接受 CRLF 和结尾换行，拒绝控制序列、方向覆盖、双宽或零宽字符。无效资源在创建
新对话或进入 raw mode 前报错。不自动搜索本机文件、下载字体或访问网络。

A 来源于 `https://emojicombos.com/lain`；原作者与再分发许可尚未核实。因此当前不将
第三方原文捆绑进 Git 或二进制，使用用户明确选定的本地文件；入口也支持之后获得明确
许可的同尺寸替代资源。资源只影响本地呈现，不上传 Kernel、不进入模型上下文、人格
或记忆。未配置时保留品牌文字和全部功能，不回退到被否定的旧肖像。

有资源且宽至少 110 列、高至少 32 行时，左侧 32 列放完整头像，间隔 2 列，右侧
聊天使用全高。其他窗口仅在 Chat 为空且无发送/审批时展示完整开场：至少 40×24 才能
容纳 18 行头像、对话标识、输入及状态。开始发送或恢复已有消息后，窄窗口收起头像，
正文优先；不足 24 行时不裁切头像。最小操作窗口仍为 40×14。

页面切换保存聊天草稿、选中行、滚动位置及是否跟随；这是有界可丢弃的前端状态，
不是持久记忆。关闭进程仍不承诺恢复未发送草稿。原生 ConPTY 验证使用显式
`--portrait-file`，图片还原实际 VT 流并为盲文选用 Segoe UI Symbol；这不能替代
实际 Windows Terminal 对所选终端字体的回退验收。

## 视觉沿革

2026-11-02 的手绘 ASCII 方案（18/8/5 行）已被用户否定并由上述本地资源方案取代。
2026-11-03 的布局图片是设计预览，后续 ConPTY 图片是实际字符流的字体渲染；两者
均不能标为已捕获的 Windows Terminal 桌面窗口。头像采用低饱和青色，使用终端自身
背景；状态、失败、审批范围和聊天输入优先。不使用主仆称谓，不通过装饰虚构经历。

## Chat 交互

| 操作 | 行为 |
| --- | --- |
| Enter | 提交当前文本；存在进行中或不确定提交时保留草稿 |
| Ctrl-J | 插入换行，Chat 和 Worker 续接输入共用；不提交草稿 |
| 终端转发的 Ctrl/Shift/Alt-Enter | 换行兼容键；Windows Terminal 默认 Alt-Enter 全屏，不将其作为主要操作提示 |
| 左右、Home/End、Backspace/Delete | 编辑 Unicode 文本；Home/End 定位整份草稿两端 |
| Ctrl-U | 清空未发送草稿 |
| Tab | Chat → Work → Devices → Chat，保留草稿 |
| Esc | 返回 Chat；审批页中关闭审批页 |
| PgUp/PgDn | 阅读正文或详情；Ctrl-End 恢复自动跟随 |
| Chat 正文上的鼠标滚轮 | 上下滚动已载入历史；上翻暂停跟随，滚回底部恢复；不修改草稿 |
| Ctrl-R / `/refresh` | 从 Kernel 重新读取，不重发任务 |
| Ctrl-Q / `/exit` | 关闭界面，Kernel 工作继续 |
| Ctrl-C | 有正文选区时复制选区；否则有草稿时清空草稿、无草稿时退出，不等于取消 Actor/Worker |
| F2 / `/copy` | 查看最近已载入回复的复制选项：纯文本、原始 Markdown、各代码块；上下键选择，Enter 复制，Esc 关闭 |
| Ctrl-O | 复制最近一条已保存的 Assistant 回复纯文本 |
| 正文拖选 + Ctrl-C | 按消息正文复制，不含头像、角色、按钮或边框；保留原有换行，排除视觉自动折行 |
| F3 / `/read` | 进入隐藏侧栏与输入框的只读阅读视图；Esc 或 F3 返回并保留草稿及原滚动位置 |
| Ctrl-Home | 回到已载入正文顶部；不是从服务器分页加载更早历史 |

## 正文渲染与复制

Chat 正文不再套四面边框，头像侧栏保留。已保存的 Assistant 消息用 Markdown
排版标题、强调、列表、引用、行内代码和围栏代码块；代码使用本地语法高亮。
普通段落最多占 96 个显示列，代码块可使用正文区域全宽。User、运行回执和流式预览
按文本显示，防止用户原文或尚未落盘的预览被当作完成回复。复杂表格、数学公式、
Mermaid 和 HTML 不做专用渲染；链接标签着色，不自动访问目标，完整 URL 保留在 Markdown 复制中。

源消息、显示行与可复制正文分开保存。选区锚定消息 ID、版本及 Unicode 字素范围，
窗口缩放和其他消息追加不改变被选中的文字；消息正文改变后旧选区与复制菜单目标失效。
中文、组合字符和 emoji 按显示列命中；独立零宽字符显示为占一列的替代符，复制仍保留源字符。
代码复制保留 Tab、真实换行和正文中的 `│`、`|`，不包含围栏、语言标签或呈现装饰。

复制由本地异步剪贴板线程执行，不调用模型或 Worker，也不通过云端读取电脑剪贴板。
只有原生剪贴板写入成功才显示成功提示；没有可用本机剪贴板时显示错误。
当前未实现 OSC 52/SSH 剪贴板转发。应用接管鼠标拖选，普通终端选区仍可能包含侧栏，
推荐使用上述正文复制功能。菜单冻结具体消息与版本，后台回复不会悄悄改变已选目标。
已失效的同步来源会清空正文、选区、菜单并撤销尚未开始写入的复制请求；
已经写入系统剪贴板的内容不承诺撤回。

阅读和复制范围限于客户端实际载入的有界历史，启动仍读取最近 20 轮，
不是完整档案浏览器。富文本最多保留 256 个条目、128 KiB 源文本、256 KiB
派生正文；单条源文本超过 32 KiB 显示明确的超限提示并禁用该条复制，
完整消息仍在 Kernel 历史中；派生正文超过 64 KiB 会标记截断。
流式预览不提供整条回复或代码复制，需等待 Kernel 保存权威消息。

W4a 不在同一对话自动排队第二个 Actor 请求。当前回复生成时仍可以编辑下一条、查看工作和
设备；Enter 明确提示等待并保留文本。不同 Worker 的执行与 Lain 对话独立，不因界面切换停止。
草稿仅在当前终端进程中保存；关闭终端不会写成记忆，也不承诺崩溃后恢复未提交草稿。

用户提交的原始文本不经过静默优化。发送使用稳定 RequestId；接收不确定时保存原始文本和
RequestId，阻止发送新的请求。`/refresh` 检查持久历史；`/retry` 由用户明确重发同一 ID 和
同一文本，不能把新草稿换进去。重试不会自动发生。

预览继续使用既有 Actor Renderer 的身份、版本和顺序规则，不能把断线前预览当作完成回复。
断线后有限重连只重新读取同一 Actor；恢复依据 Kernel 的持久快照，无额外模型调用。
`/stop` 显式请求取消当前 Running Actor，不用于取消 Worker。

`/help` 展示入口命令；`/work`/`/dashboard` 切到 Worker；`/devices` 切到设备。
命令占满一份草稿且经 Enter 才执行；粘贴多行中的命令不会被逐行执行。
工作通知显示在同一对话正文；`/seen` 显式标记当前显示的通知已读，读取通知不等于控制 Worker。
界面最多保留 100 条待确认通知；未展示的不会自动确认，完整通知仍可用原有 notices 命令读取。

## Work 与返回 Lain

Work 列表显示 Kernel 本地受管 session，以及当前对话实际关联的设备任务，明确区分
Backend/设备、状态和 Workspace；不会为远端会话伪造云端本地 session。
上下键选择，Enter 对本地 Worker 打开已有详情/时间线/输入/审批界面；对远程工作打开
对应设备任务详情与远程权限入口。
观察不会隐式 resume、启动新 Worker 或重放旧 prompt。其输入明确发给当前 Worker，
聊天页输入明确发给 Lain；两者不共用草稿。

详情沿用已有明确的工作控制与审批能力。Ctrl-Q 关闭 Worker 子界面并返回同一 Lain 对话；
Esc 保留该界面原有的返回 Worker 列表语义。进入和返回时分别释放并恢复终端输入读取器、
alternate screen 与 raw mode，不能有两个输入消费者争抢键盘。
返回后 Lain 的草稿和对话保持，后台输出继续从 Kernel 恢复。

这个入口是 Lain 的结构化 Worker 界面，不是伪装的 Codex 原生终端。
原生完整终端接入仍取决于 Backend 的真实能力；没有该能力时不显示可用入口，
也不解析终端绘制内容来模拟受支持的协议。

## Devices 与远程任务

设备列表显示注册状态、有效期是否过期和最后收到报告的时间；Active 不等于“在线”。
Enter 进入所选设备的任务摘要，再 Enter 进入该任务完整详情。
设备登记与摘要页仍只读；设备任务详情现有 F4 精确权限检查，按后端实际可选项决定。
自然对话 `device_queue` 提案沿用 Lain action 的明确确认；直接 CLI 可用
`device command queue --conversation` 关联原对话。不因进入页面启动服务或派工。
任务取消现可用 F8 明确审阅；同会话追加见上方 W4c。只读服务诊断与显式运行方法见
[原生服务](DEVICE_HOST.md)。当前入口不安装或自动启动服务。

新增管理员 GET `/v1/devices/{id}/commands`：返回当前设备已有命令的有界摘要，
按创建时间降序排列，同时间以 ID 排序；设备凭证无权调用。摘要只含 ID/revision/state、
cancel_requested、profile/workspace ID、创建和截止时间，不复制原始任务、输出或审批。
沿用每设备最多 128 条命令的现有容量和到期/撤销投影，不新增迁移或执行权。

详情来自已有单任务 API，明确区分云端命令状态、取消请求、设备执行阶段、实际回执、
有界 output tail、命令失败数、历史不完整标记和未验证路径引用。
Unknown 不能显示为完成，Cancel requested 不能显示为已经取消，报告路径不能冒充上传的文件。
设备页面每 5 秒仅在可见时读取一次；网络失败保留上次缓存并标注错误，不虚构刷新成功。
页面与设备/任务 ID、请求代次绑定，迟到响应不得覆盖另一个设备的详情。

## 审批

F4 或 `/review` 打开当前 Actor 的 Proposed action；展示该动作的完整 typed ToolCall。
派工与追加的 work.create/work.send/device.queue 动作还展示 Changed/Unchanged、带消息 ID
的原始记录、实际发送文本和完整替换差异；JSON 字符串保留空白与控制字符。多条原始消息
分别展示，不伪造一条合并原文；缺少可核对原文时不能批准。Changed 只表达文本不同，
不代表已经实现 prompt 优化器或自动证明语义忠实。远程派工的稳定 RequestId 一并展示。
它不是 Worker 权限，也不让聊天语气替代审批。
用户逐页读完整份范围后，Ctrl-Y 批准一次或 Ctrl-D 拒绝；Esc 关闭，无默认同意。
阅读进度绑定当前 payload 和行宽，跳过中间范围不能启用批准。
范围、action ID 或 revision 更新后旧审批页失效。决定发送前再次检查同一 ID/revision/
Proposed 状态/完整工具文本及原文比较，发送后等待 Kernel 的权威状态。
不确定的决定结果先读取，不自动重发或把本地点击当作 Worker 已应用。

Worker 原有审批页继续维护自己的范围展示和可选项。设备任务中的 F4 现展示完整远程
范围，逐页阅读后仅提供实际可选的 Ctrl-Y/Ctrl-D/Ctrl-K；发送前读取当前任务，服务端
和设备端分别复核。回执、执行应用和不确定结果的处理见[远程权限](DEVICE_WORK.md#remote-permission-review)。
