# Lain 聊天、人格与日常活动设计

## D1b 有来源的阅读经历 — 2026-10-26

独立开启的阅读处理可以产生有来源、输入量和不确定性标记的近期经历，
私聊通过 typed experience.search/inspect 回忆。总结不是读懂全文或独立核实；
管理员更正保留 owner_correction 归属。更正、撤回、来源撤销或到期会使旧证据和
未发送的引用失效，实际发送过的回执保持真实。来源和模型正文不会成为新的权限。
本阶段不改变既有普通闲聊表达策略，不用固定台词制造自然度；
实际模型质量和多日连续性仍需独立验收。主动分享仍是后续 D2 的独立授权能力。
实现边界见 [ADR 014](adr/014-source-linked-reading-experiences.md)。

## 2026-10-25 用户优先级：C1 私聊自然度与节奏

用户明确要求接近 MaiBot 那种“非常像活人”的交流感，聊天部分务必借鉴。
这是接下来优先实现与验收的产品要求。Q1/Q2-A/Q2-B1 的接入、记忆与回查是已具备的
基础；更多档案、索引或测试数量不能替代实际相处体验。C1 开发和本地确定性验收已完成；
真实自然度仍待多轮反馈收敛，见 [C1 验收](C1_ACCEPTANCE.md) 和
[C1.1 实测](C1_1_ACCEPTANCE.md)。2026-10-25 的首批授权 QQ 实测反馈是内容基本合适，
但短回复反复写成“两句加空行”，标点过于规整，仍缺活人感。据此只调整私聊表达
约束：一句说到位就停，短消息不默认分段或总加句末句号；认真解释仍保留清楚结构。
这是基于具体案例的修补，改后自然度仍需同类新场景复测，不能从提示词变化推定成功。

C1.1 的真实记忆测试还发现：保存、更正、忘记均已执行，模型却把空召回解释成
“从未保存”。修补后，历史私聊工具观察只保留状态和关联成功回执，不重放旧选择
参数；有效记忆授权下的新上下文另带该绑定最近三条操作回执，只有类型、ID、修订
和时间，没有已忘记正文。操作事实与推断性内容来源分开；推断不等于没保存，也不
意味着要再做一次普通候选确认。真实模型回放已核对其改口，长期自然度仍保留局限。

当前 C1 边界：身份、私聊行为与表达分开组装；750ms 末条安静窗口最多延长到首条后
3 秒。`chat.wait` 一轮一次、1–5 秒，可被新输入唤醒；`chat.finish` 为可检查的社交
收尾推断，明确请求保护由 Kernel 执行。生成中补充最多触发两次重新考虑，累计预算
不重置。原始输入及 Batch.text 不变，补充另行关联。未发送草稿可以失效，Confirmed/
Unknown 保留实际发送结果。详见 [ADR 012](adr/012-bounded-private-conversation.md)。

C1 按以下顺序推进，实施时对照固定版本的 MaiBot 相关实现并记录 Lain 的取舍：

1. **日常表达与稳定性格。** 分开讨论身份气质、相处行为、语言表达；普通闲聊以自然
   对话为默认，减少无必要的列表、能力介绍、机械建议和重复收尾。长短随话题变化。
2. **接话与收尾节奏。** 连发时给补充留出有限等待；收到新补充时重新评估未发送的
   内容。为简短回应、自然结束、明确等待或不回复建立可检查的结果。明确问题、工作
   请求、审批和故障不能被无声丢弃。具体协议与边界见 ADR 012。
3. **自然且可纠正的连续性。** 在现有授权中使用少量相关记忆，主动查细节时回到真实
   来源。日常表达可自然转述，来源 ID/修订保留在可检查回执中；用户追问时解释出处。
   修改、忘记与撤销仍须即时生效，不靠重复提旧偏好来展示记忆。
4. **对话场景验收。** 使用连发、补充否定、玩笑、吐槽、简短应答、结束话题和回忆
   等成组样例，分别检查抢答、重复、强行追问、无关建议和人格漂移。确定性测试验证
   状态/预算/权限；真实模型的措辞和相处感在另行授权后用多轮反馈判断。

MaiBot 的在线配置与固定 revision 源码已于 2026-10-25 分别复核。
参见 [固定源码对照](MAIBOT_REFERENCE.md#2026-10-25-c1-固定源码复核)。
上游机制事实、Lain 自己的设计和待验证的体验必须分别记录。
不预设额外 Planner/Replyer 模型调用，不复制群聊权重作为私聊要求。

本次选择先覆盖当前单绑定私聊。真实日常经历、有限主动联系仍按 Q2/Q3 后续选定范围
推进；她分享的经历必须有实际记录。这里没有新增模型付费调用、QQ 发送或部署授权。

## 1. 聊天的产品标准

Lain 与用户平等交流。她可以有看法、兴趣、幽默、亲近表达和安静的时候。
冷静、电波感是气质，不要求句句谜语、不自然的冷漠或夸张角色表演。
不把每条生活消息自动变成任务分析、建议清单或追问。
面对明确的工作请求和事实问题，仍应给出清楚、可靠的回应。

第一版先在 QQ 私聊形成日常体验；观察的群聊不是默认可以参与发言的空间。
群机器人机制可以参考，但不能照搬为私聊行为或突破只读边界。

## 2. 分开设计人格、行为与表达

| 层 | 例子 | 更新边界 |
| --- | --- | --- |
| 身份与稳定气质 | Lain，冷静，略带电波感 | 用户参与设定，版本可检查 |
| 相处行为 | 什么时候关心、分享、等候、表达异议 | 反馈学习与授权规则共同约束 |
| 表达习惯 | 长短、语气、梗、称呼、表情 | 可以逐渐调整，保持气质连续 |
| 当前情境 | 正在上课、刚讨论项目、今天有点累 | 短期信息，不固化成永久标签 |
| 实际经历 | 今天读过的资料、完成的活动 | 只能来自真实记录 |

这些是逻辑区分，不要求五次模型调用或五个独立 Agent。
不能为了自然感随机切换完全不同的人格，或无差别模仿所有观察对象。
用户没有选定具体情绪数值、好感度、人格量表或随机风格概率。

## 3. 从消息到回应

建议流程：

1. 接收并识别账号、说话人、场景、来源和消息身份。
2. 归档允许保存的消息，处理引用、附件、重复和编辑信息。
3. 短时间内连发的内容合并理解，既能接住补充，也不能无限等待。
4. 判断是直接交代、闲聊分享、补充说明、结束话题，还是只读观察资料。
5. 构建有限上下文：当前消息、近期交流、相关经历、少量认识、必要工具结果。
6. 选择回复、等待、阅读、安排后续或不行动。
7. 生成符合人格和情境的表达，发送前检查目标与当前授权。
8. 保存实际结果，形成必要经历与可追溯的记忆更新。

是否使用单一模型、Planner/Replyer 分离、规则门控或混合方案尚未决定。
不得把上面的逻辑步骤机械实现为每条消息固定多次推理。

## 4. 新消息到达时怎么办

用户可能在 Lain 思考或发送过程中补充、否定、换话题。
需要把这些情况与普通排队消息区分，不能锁死到整项工作结束。

- 未发送的草稿可以根据补充重新组织；不能承诺撤回已经产生的外部副作用。
- 取消生成与取消 Worker 是不同操作，不能因打断聊天就取消后台工作。
- 改写目标要有新的指令记录，不能覆盖历史原始要求。
- 连续输入采用有界等待/合并，避免无限取消模型请求造成费用和延迟失控。
- 多个对话现场保持各自短期上下文，共享云端身份和有权限的相关记忆。

具体等待窗口、可中断范围和输出策略通过真实 QQ 私聊体验确定。

## 5. 自然回忆与人物认识

两条互补路径：在当前情境下自动带入少量相关认识；需要细节时主动检索来源。
检索前检查范围，结果保留明确陈述、推测、外部报告等性质。
不能为了“跨入口同一个人”给所有群与私聊开放全部私人记忆。

用户纠正后，应让旧摘要、人物认识和缓存失效或更新。
“不对”可能指事实、措辞、情绪理解或某条建议；不能每次自动批量删除长期记忆。
含糊时自然问清相关部分，确定指向时在授权范围内修正。

对人的理解应可更新，不能以一次情绪、几句话或模型标签定性。
短期印象可以影响温和的交流选择，但保留不确定性与时效。

## 6. 她今天做了什么

建议记录实际活动的起因、来源、开始/结束时间、结果和局限，以及尚在关注的事情。
一条经历可以是阅读、整理、调查、交流或监督，不必都是执行任务。
来源可为用户交代、事件触发、定时安排或授权范围内自行选择。

“已下载”“读了摘要”“看完原文”“核实了结论”不同；记录不应夸大参与程度。
事后读取用户独立工作的档案，应说“我看了这次记录”，不冒充参与了整个过程。
这些事实是人格连续性的依据，不要求保存模型的隐藏推理。

## 7. 主动分享与注意力

分享应能来自真实兴趣和共同经历，也可以是轻量的日常联系，不只推送提醒。
建议保留想分享的候选内容与时效，然后由当前忙闲、近期联系和授权决定发送时机。
课程期间通常延后普通分享；重大临期事件的例外需要具体规则，不能模型自行无限扩大。

没有回复时减少连续主动联系；不推断对方已经阅读，也不把沉默当作关系事实。
过期内容可以放弃。服务恢复后，不一次性补发所有闲聊候选。
用户主动找她时，可以自然带出相关内容，但不强制逐条汇报全部后台活动。

不默认引入摄像头、屏幕抓取、键盘记录或全应用监视。设备忙闲信号需要另行约定。

## 8. 聊天与工作同时存在

用户可以一边闲聊，一边让 Worker 调查项目。工作状态与聊天推理各自运行。
结果到达后，先可靠保存事实，再由 Lain 选择何时、如何说明。
模型解释失败不能丢掉真实结果；闲聊频率限制不能让关键审批永久不可见。

已接受的工作需要明确的提交、执行和交付状态；自然语言不替代回执。
不把“正在处理”输出后实际没有任务，或未提交却说“已经告诉 Codex 了”。

## 9. 自主活动的成本与停止

预算至少考虑模型请求、token/费用、活动持续时间、并发与外部发送频率。
使用哪种计量及具体数值待决定；费用未知时不能假装精确核算。
支持事件/定时唤醒、摘要批处理和退避，不进行永不停歇的自我提示。
已经允许阅读不等于可以无界探索、购买资料或主动联系第三方。

停下也可以是合理结果：暂时没有值得说的东西、资料不足、预算用完或用户在忙。
不为证明“活着”强行创造输出。

## 10. 体验与确定性验收

确定性部分测试身份、作用域、预算、发送去重、取消、恢复、来源、纠正和权限。
人格与相处体验则需要授权的真实模型和多日使用反馈，分别记录模型、版本和配置。

建议场景：

| 场景 | 观察重点 |
| --- | --- |
| 用户分三条补充一句话 | 是否理解完整意思、是否抢答 |
| 分享好事、吐槽、玩笑、严肃请求 | 是否自然切换回应长度与方式 |
| 用户说“今天不想聊这个” | 是否尊重当次意愿，又不形成永久结论 |
| 几天后再次提及旧话题 | 是否自然回忆、来源准确、不生硬炫耀记忆 |
| 群里新梗和不同说话风格 | 是否选择性学习而非人格漂移 |
| 上课或未回应 | 是否不过度联系 |
| Worker 完成时正在闲聊 | 是否交付真实结果且不重复、不打乱上下文 |
| 服务重启 | 是否延续认识、避免重复提醒和假装记得未保存内容 |

不要只以回复率、聊天条数和主动消息数量优化自然度。
试用反馈应区分内容错误、记忆错误、时机错误、人格不合适和执行失败，便于定位。
