## 来源日期与回答日期分开 — 2026-11-06，已部署

  时间的引用所用日期锚点；不能用在接收时间回退、别的来源日期或已保存记忆上。

## 产品目标

在明确授权的 QQ 来源中接收消息，用户问“昨天有什么重要消息”时形成有出处、范围和
不确定性说明的简报。用户能够追问一条原文，选中事项保存，再查询、更正或忘记。
保持原始消息、派生简报与语义记忆分开，不把群成员发言当作用户偏好或执行授权。

本阶段不包括主动推送、Telegram/水源接入、新的 Worker 后端或 Web 前端改版。
QQ 与终端继续使用同一云端身份，来源适配器保持独立。

## 已有基础与明确缺口

- 原始档案、来源身份、有限导入授权、记录去重、更正、忘记和授权修订已存在。
- 独立 QQ 知识服务支持选定私聊/群来源、真实消息与图片描述、撤回和连接缺口。
  Kernel 已有独立只读桥接与有限定期同步，不能为本阶段复制整套采集和存储。
- 普通 `archive_search` 只在授权私聊里从最多 100 个候选中选择每轮三条原始记录。
  它适合小范围回查，不能把这三条包装成完整的一天。
- 档案阅读和档案写入记忆是独立的私聊授权；普通终端 Actor 不因持有 owner API
  凭据就自动继承某个 QQ 私聊的消息阅读权。终端简报需要明确的受众契约。
- 独立服务已有有限缺口报告；来源限定的 changes 响应现在可携带最近最多 20 条历史
  报告，Kernel 保存同一快照并在终端展示。服务只保留全局最近 1000 条，且未标记来源
  授权时期，不能用来证明当前授权期间的完整缺口或实时连接。旧服务不返回此字段时，
  兼容为空。报告时间是上游服务收到报告的时间，不是实际断连/恢复时间。
- 2026-11-05 的只读现场检查发现云端档案来源数为零；现有 QQ 私聊回复绑定不等于
  档案导入、群采集、跨会话阅读或长期记忆已获授权。

## 第一部分：只读来源状态

实现接口：

```text
GET /v1/archives/status
GET /v1/archives/sources/{source-id}/status
lain archive status
lain archive status <source-id>
```

全部使用现有 owner 鉴权与 `Cache-Control: no-store`。只读取本地已登记来源，最多 64
项，不访问 NapCat/知识服务网络、不读取消息正文、不启用授权、不调用模型。

状态分开表示：

- `import_state`：导入授权 disabled/enabled/expired；enabled 不代表采集连接在线。
- `latest_received_at_ms`：当前授权修订实际入库的最后接收时间；重复导入不刷新它。
- `latest_reported_occurrence_at_ms`：当前修订中来源声称的最近发生时间，不是接收时间。
- `retained_body_count`：当前修订未过保留期限的存储文本数，不是当前会话可阅读数。
- `latest_read`：当前导入授权修订的最近读取结果；旧修订的成功/失败不能冒充新接收。
- `upstream_snapshot_fresh`：原始授权和上游快照租期当前有效，不证明 QQ 持续接收。
- `synchronization`：既有有限读取计划、用量、下一时间和停止原因，不是采集连接。
- `receiving_now`：当前仍为 null，因为尚未接入实际采集在线证据。

上游快照中的可选 `coverage` 为有限历史，包括连接无补回、断连缺口、媒体不可用和
观察器投递失败。事件按上游序号倒序，带服务记录时间，最多 20 条。未知种类、超限、
乱序、重复序号或晚于快照的报告会拒绝整页，不会刷新来源新鲜度。过期快照仍可作为
管理历史查看，界面明确标记失效，不作为模型的当前来源证据。

终端 Chat 输入 `/sources` 打开状态入口（查看只读，G 的显式管理见本文开头）。Enter 进入所选来源，Esc 返回列表
或聊天，Ctrl-R 重读，详情用滚轮/PgUp/PgDn。没有来源时明确显示“尚未接入”，不会
回答“昨天没有消息”。来源读取结果遵守既有代际与来源失效清理，不能恢复旧页面正文。

第一部分需匹配服务端/客户端构建；尚未升级的个人实例不自动获得这些接口。

## 配置与停止：沿用已有独立授权

这些操作必须先由用户选定实际来源和范围。下面只有操作路径，不是启用授权。

1. 独立知识服务仅选择指定账号/群/会话，同时核对观察器本地 allowlist 和服务端
   source 授权。双端都选中才接收。参见 [知识服务说明](../services/qq-knowledge/README.md)。
2. 用 `lain archive register --file <来源文件>` 登记同一规范来源身份；登记默认关闭。
3. 用既有 `lain archive enable` 明确设置当前修订、到期、保留期及记录上限。
4. 若选择知识桥接，显式配置私有 `LAIN_KNOWLEDGE_CONFIG`，使用间接 SecretRef 的只读
   凭据；按已有 `knowledge-pull` 和 `knowledge-sync-enable` 指定当前来源修订、有限
   请求数、读取间隔和到期。不得把“无限模型额度”解释成无限采集或无限同步。
5. 用 `archive recall-enable` 为指定私聊设置独立的来源/导入修订、时区偏移和到期；
   保存记忆还需要独立授权，不能自动复用七天试用或扩大共享范围。

停止同步到 Lain 使用 `archive knowledge-sync-revoke <source-id> --revision N`，
撤销 Lain 该来源导入/披露使用 `archive revoke <source-id> --revision N`。先读取
当前修订再操作，不用旧修订重试。它们不自动关闭独立知识服务的上游原始采集；需要
另行关闭该服务来源及观察器对应 allowlist。独立缓存、备份及此前模型披露不等于被
物理擦除。现有 CLI/API 的完整契约见 [档案接入](ARCHIVE_ACCEPTANCE.md)、
[来源回查](ARCHIVE_RECALL_ACCEPTANCE.md)及相关 ADR018/021/022/023/025。

### 已选定的会话授权与按日证据清单

max_records。撤销 scope 为 null。应先看目标会话与来源当前修订；不能套用演示 UUID。

prepare 固定当时计算的昨日半开时间窗，按归档序号遍历选定来源的候选。独立最多

不存原文、摘要或语义记忆。重启或跨日精确重试仍返回原清单；同身份改请求冲突。

分页最多 8 条完整文本、合计 16 KiB 文本，逐页前复核全部选中记录及授权。不会为了
塞入页面而截掉通知末尾。更正、忘记、撤销、过期和上游失效会拒绝继续读旧清单。
清单最多有效一天，且不超过授权/文本保留到期。后来收到的记录不在冻结快照内，

### 有限模型批处理：本地 schema034

```text
POST /v1/briefing/{conversation}/manifests/{id}/process
     {"from_index":0}
GET  /v1/briefing/{conversation}/manifests/{id}/batches/{from_index}

lain archive briefing-process <conversation> <manifest-id> --from-index 0
lain archive briefing-batch <conversation> <manifest-id> --from-index 0
```

process 只启动这一批，不自动运行整份清单。它复用现有 Actor、Responses 适配、超时、
中断和统一推理账本（reason=briefing）。每批最多 4 条完整原文、16 KiB 文本、一次模型

最多 8 条；模型批次的 next_index 应读取批次结果，不能套用证据页的游标。

执行在独立的内部处理会话中，不复制来源正文到用户消息，不读取聊天历史或派工状态，
没有工具、私聊、语义记忆或 Worker 能力。关闭请求端不会取消已启动批次。相同清单和
起始位置精确恢复原 Actor；Unknown、失败或重启中断不会被再次启动。

输入准备之后、实际推理记账之前也复核 run 未停止/到期。

报告每页最多 4 项、整体最多 12 KiB；只减少完整条目，不截标题、摘要或不确定说明。
引用另带 `quote_excerpt`：已核验引用的逐字 UTF-8 前缀，最多 128 字节，在字符边界截取，
并通过 `quote_excerpt_truncated` 明示是否截短。即使未截短，它也只是选定引用，不证明
是完整原消息；完整原文仍需 inspect。摘录保留各自的 `text_origin`，图片推断不会因此
变成发送者原话。前台报告和 Actor 读取均先用当前密钥规则检查完整引用，再截取摘录，
防止截取边界把密钥变成未检出的前缀；原有整页过滤与来源依赖不变。`next_after` 按实际

必须保留，不能合并后重新编号。引用含真实来源 ID、版本、时间、文本来源和由 QQ 来源
身份生成的可读标识（例如 QQ群及群号，不伪造群名）。普通列举使用这些出处即可，只有
用户追问原文时再读某个具体引用。一次 inspect 返回一条完整原文及其来源身份。

后续页游标继续按保留的完整条目计算，不提高报告上限。
